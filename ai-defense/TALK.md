# Il security engineer che già AI

- **Issue**: #2
- **Thesis**: La security non può essere un privilegio di chi ha budget. L'AI generalista che già usi per scrivere codice — usata come sistema (skill, tool, agenti, scope ristretto) e non come oracolo — è il moltiplicatore che permette a chiunque di fare assessment serio sul proprio codice e sulle proprie dipendenze, senza comprare un altro vendor.
- **Audience**: Dev di livello vario (junior → senior), tech lead, indie maker, OSS maintainer, studenti. Pubblico misto come da format ComeToCode.
- **Takeaways**:
  - Lunedì mattina: prendi una skill di security review già pronta (la `/security-review` di Claude Code, o le skill nel repo di Argus) e lanciala sul tuo repo. Zero codice, non reinventare la ruota.
  - Human in the loop: l'AI è un collega fallibile. Tu sei il progettista — se un collega ti dice una cavolata e ti fidi ciecamente, l'errore è tuo. Il giudizio non si delega.
  - Scala per gradini, non comprare: skill pronte → skill tue → MCP/tool deterministici → agente. Il gradino finale già assemblato e open source esiste: [Argus](https://github.com/argusappsec/argus).
- **Outline**:
  - (8min) Apertura + problema, arco unico senza stacco: buzzword a specchio (AI ovunque vs security a budget zero), "Feeling secure? / You just haven't been breached yet", i tre numeri con fonte (27s breakout CrowdStrike GTR 2026; 454k+ pacchetti malevoli Sonatype 2026; 4.8M gap ISC2 2024), GTG-1002 80–90% (Anthropic nov 2025), superfici d'attacco (secrets/deps/images/infra), nessuno presidia (people/tools/training), domanda ponte "You already use AI for code — why not for security?"
  - (6min) La tesi: il security engineer con cui già lavori + beat anticlimax "AI hallucinates" + human in the loop (collega fallibile, giudizio non delegato, callback GTG-1002) + sistema-non-oracolo (chat mockup vs pipeline question/work/answer)
  - (17min) La scala con il caso reale dentro: ① skill pronte (run `/security-review` nel terminale + slide costi/privacy subito dopo il run: centesimi, stesso provider del coding, self-host possibile [numeri da inserire]) → ② skill tue + caso reale RedCarbon come spot-the-bug (codice TS dimostrativo di fantasia a tutta pagina, la sala cerca il bug → reveal broken access control → tabella del caso → habit; 4 slide) → ③ MCP/tooling deterministico (Trivy MCP, semgrep, osv-scanner, gitleaks) con proof nel terminale (run reale gitleaks: chiedi all'AI, trova il secret, gli chiedi di sistemarlo) → ④ knowledge base nel repo come ponte (ADR, CONTEXT.md, docs-as-code, skill tipo grill-with-docs: ogni sessione AI parte calda) + anatomia agente (soul, memoria, context, daemon; onestà: il daemon non è definitorio, è la scelta di Argus)
